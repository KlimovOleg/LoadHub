# ADR-0001: MariaDB, собственный Docker-сетап и отдельное SPA

- **Статус:** принято
- **Дата:** 2026-09-29

## Контекст

LoadHub — учебный проект уровня коммерческой разработки (мини-TMS: грузы, водители, диспетчеры).
Цель — освоить Laravel 13 + Vue 3 так, чтобы опыт напрямую переносился на рабочие проекты,
которые используют MariaDB и имеют отдельные клиенты (веб и мобильные приложения).

## Решение

1. **БД — MariaDB 11.4 LTS**, драйвер Laravel `mariadb`. Тесты с первого дня идут на MariaDB
   (база `loadhub_testing`), SQLite не используем: у него другое поведение `lockForUpdate`,
   нет `whereFullText`, иначе работает JSON и типизация.
2. **Собственный docker compose вместо Laravel Sail.** Один образ PHP (multi-stage: `base → dev`,
   позже `prod`), процессы разнесены по контейнерам. Сервисы добавляются по мере надобности.
3. **Фронтенд — отдельное SPA** (Vue 3 + TypeScript + Vite) в `frontend/`, общается с Laravel
   только через HTTP API. Аутентификация — Sanctum SPA (cookie + CSRF).

## Последствия

- `+` Опыт совпадает с рабочим стеком (MariaDB), тесты ловят реальные особенности движка.
- `+` Docker-сетап пригоден для развития в prod-образы и CI без смены инструмента.
- `+` API не привязан к одному клиенту — готовность к мобильным приложениям и партнёрскому API.
- `−` Больше начальной настройки, чем с Sail или Inertia.
- `−` Нужно следить за настройками Sanctum/CORS/cookie для SPA (этап 2).
- `−` `backend/.env` не передаётся в контейнер через `env_file` — иначе `phpunit.xml`
  не сможет подменить базу на тестовую (см. `docs/laravel_intro2.md`, раздел 5.3, ловушка 4,
  и `docs/install_truble.md`, раздел 2.6).
